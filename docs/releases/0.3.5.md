# Event Notes 0.3.5

Calendar refreshes now show their progress, and a failed refresh names the step that failed.

- **Refresh progress.** The refresh icon, the **Refresh calendars** command, and turning a subscription on or off (in the **⋯** menu or in settings) show a notice that follows each calendar through six steps: check the URL, download the feed, check the response, read the events, update Event Notes, and save the result. On success the notice closes by itself.
- **Failures name the step.** When a step fails the notice stays until you click it and lists the calendar, the step, and the reason, for example *Work: failed at step 2 of 6, “Download the feed”. The calendar server returned HTTP 404.* Reasons are fixed messages; no feed URL or feed content is shown. Background refreshes stay silent, as before.
- **Turning a subscription on retries it at once.** Previously, a subscription that had failed waited out its retry delay (up to an hour) even after you turned it off and on again, so it could look stuck. Turning it on now fetches the feed immediately; the refresh icon already did.

## Install

**Download the [Event Notes 0.3.5 ZIP](https://github.com/rightson/obsidian-event-notes/releases/download/0.3.5/event-notes.zip)**, extract it, and copy the `event-notes` folder into `<Vault>/.obsidian/plugins/`, or install through BRAT. Moving from Calendar Pro is covered in the [installation guide](https://github.com/rightson/obsidian-event-notes/blob/main/docs/manuals/INSTALLATION.md#moving-from-calendar-pro-or-calendar-note).

## Compatibility and verification

Requires Obsidian 1.14.5 or later on desktop. `npm run typecheck`, `npm test`, and `npm run package` pass. The progress steps, failure reporting, and the immediate retry have automated coverage. The notice's layout was checked in a browser mock built from the plugin's stylesheet; the notice has not had native QA in Obsidian.
